pi-linehash-edit

Stateless, checksum-guarded line editing for pi coding agents.

A line number says where; one checksum says which version. Think of the checksum as a tamper seal on the file the model just read. replace checks the seal before it writes — if anything changed after the read, even somewhere else, the seal no longer matches and the edit is refused rather than applied to a version the model never saw.

What it guarantees

  • every read returns one whole-file checksum, then line│content rows — the checksum is paid once at the top of a response, not repeated on every line
  • replace edits numeric [start, end] ranges, applied atomically against the exact snapshot the checksum names; positions resolve against the original, so one call can change many disjoint ranges
  • any raw-byte change after the read — anywhere, not just the edited lines — makes the checksum stale, and nothing is written on a mismatch
  • a stale replace hands back the file's current state and fresh checksum inline, so the model re-derives and retries in one call instead of a separate read
  • guards reject a pasted read row so the line│ prefix can't leak into content; UTF-8, BOM, and mixed line-endings are normalized, invalid bytes shown as U+FFFD
  • stateless: no cache, no per-session memory — the bytes on disk and the 22-character checksum are the whole protocol; images are handed back to pi's own reader

Install

pi install npm:pi-linehash-edit

Requires pi 0.79.0 or newer. On session start it replaces pi's read, registers replace, and disables the built-in edit tool.

A complete edit

read returns one checksum followed by numbered lines:

checksum:4vQj8YqLw7R3tP0uN2mKxA
1│const a = 1;
2│const b = 2;

Carry that checksum straight into replace, naming only the lines to change:

replace(path, "4vQj8YqLw7R3tP0uN2mKxA",
        [{ range: [2, 2], content_lines: ["const b = 3;"] }])

Why lines, not patches

Many edit tools ask the model to reproduce an old block of text exactly before replacing it. One wrong space, tab, or repeated line makes that ambiguous, and patch formats add a grammar the model must get right. Here the model points at line numbers and proves freshness with a checksum — no re-transcription, no patch syntax, and the tool would rather stop and ask for a fresh read than write to a file it can't prove the model saw.
